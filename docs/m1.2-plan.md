# ORX M1.2 Plan: Observability Completion

Status: frozen baseline (2026-10-04). Amendments append at the bottom with
dates; the baseline text above them never rewrites silently. This document
is the authority for M1.2 scope and contracts, in the same spirit as
`docs/m0-plan.md` and `docs/m1-plan.md`.

M1.2 is developed **through ORX itself** (dogfood): one Goal (G002) carries
the milestone; this run's own `.orx/state.db` is the acceptance fixture —
the first run observed end to end.

## Why (evidence from R001, measured 2026-10-04)

| Gap | R001 fact | Root cause |
|---|---|---|
| No attempt↔session link | 0 columns, 0 code paths | never designed |
| Host usage invisible | 28 host attempts, 0 token observations | no capture path exists |
| CLI usage partially visible | 12 of 37 CLI attempts observed (~32%) | event loss per adapter path |
| Spans incomplete | 6/6 CLI workers missing `started_at` (all cursor-strong) | `dispatch.py` creates the CLI worker attempt `started=False` and only ever stamps `ended_at` |
| Wall clock not reconstructible | `runs` has only `created_at`/`updated_at` | no lifecycle timestamps |

## Goals

1. **Session association** — every attempt can carry an opaque native
   session reference; ORX stores it, never resolves it.
2. **Host usage capture** — host-executed attempts can receive usage
   observations (`host_report` source, accuracy explicit).
3. **Span + lifecycle completeness** — every attempt gets both timestamps;
   runs get lifecycle timestamps; wall clock no longer depends on
   `updated_at` heuristics.
4. **CLI coverage honesty** — raise token-observation coverage where the
   events exist; keep `accuracy` truthful; every miss has a recorded reason.
5. **Read contract for external analysis** — a documented, stable,
   read-only contract over `.orx/state.db` so out-of-repo tooling can
   rebuild reports.

## Non-goals

- **The analysis layer itself lives outside this repo** (user decision,
  2026-10-04): `~/Sources/Tools/orx-analytics/` — the six-metric report,
  cross-project index, ZCode-session join, manual-ledger dedupe. M1.2 only
  guarantees the data and the contract it consumes.
- No token normalization across runners (Cursor `cached` may exceed
  `input`; R001: cursor-economy 410k input vs 5.6M cached). No token→fee
  conversion without a billing basis.
- No routing/effort strategy changes (that is the *consumer* of this data;
  roadmap order: observability first, strategy tuning last).
- No new plan-schema version; no changes to verification semantics.

## Invariants that M1.2 must not break

- All M0 invariants (exit codes 0/1/2, `--json` envelope, `objective`
  keys, one active Goal, idempotent verification, doctor flags ≡ adapter
  Required, config reads never write).
- SQLite: refuse missing/newer `schema_version`; migrations are additive
  functions keyed by integer version with backup-replace-restore; widening
  a CHECK constraint reuses the same rebuild framework (P4 precedent).
- `unknown` accuracy stays legal; observations are never fabricated.

## Phase breakdown

Single revision preferred (M1.1 precedent): tasks dependency-gated,
replan only on wrong assumptions. Three phases:

### P1 — schema & capture (schema v5)

- `attempts.session_ref TEXT NULL` (additive column). Opaque string; set
  by callers, parsed from captured CLI output where the harness exposes a
  session/thread id (codex JSONL session id; cursor when present); never
  synthesized.
- `runs.started_at / runs.completed_at NULL` (additive columns) set on
  lifecycle transitions.
- `usage_observations.source` CHECK widened with `host_report`
  (backup-replace-restore rebuild).
- Host stamping: `--session` flag and `ORX_SESSION_REF` env on the
  commands that create or claim host attempts (`task claim`, plan submit
  path); stamped onto the attempt row.
- Span fix: stamp `started_at` when the CLI worker attempt is created
  (`dispatch.py` worker path currently creates `started=False` and only
  stamps `ended_at`); regression test: no completed attempt may lack
  either timestamp.

### P2 — coverage & contract

- Diagnose the CLI observation gaps per role (R001: verifier 10/27,
  worker 1/6, planner 1/4): which invocation paths drop usage events
  (output capture modes, truncation, non-JSON streams). Fix what drops
  events that the harness actually emitted; misses the harness never
  emitted stay `unknown`, with the reason recorded on the attempt.
- `orx usage record --attempt N --input N --output N [--cached N]
  [--accuracy exact|estimated]` — writes a `host_report` observation;
  `orx usage --json` includes it.
- `docs/observability-contract.md` — the read contract: tables and
  columns (attempts, usage_observations, plan_revisions, tasks,
  verifications, task_events, runs), join keys
  (`project_id + run_id + revision + task_id + attempt_id`; short ids
  repeat across projects and revisions), per-runner token-field semantics
  (no `input − cached` normalization), span-sum ≠ wall-clock guidance,
  accuracy vs coverage stated separately, `schema_version` stability
  rules, manual-ledger dedupe by source tag.
- `orx status`/`orx usage --json` surface `session_ref` and run lifecycle
  timestamps where consumers need them.

### P3 — dogfood + report

- This run is the fixture: host attempts carry `session_ref`; every
  attempt has both timestamps; the run row carries lifecycle timestamps;
  CLI observation coverage is measured against R001's baseline with every
  miss explained.
- Host-side deliverable (outside the repo, not a run task):
  `~/Sources/Tools/orx-analytics/` — six-metric first report (交付质量,
  交付消耗, 完成时间 with 执行时间之和与用户等待时间 separate,
  一次验收通过率, 返工含原因, 数据覆盖 per dimension). The P3 task
  invokes the script if present, else the documented queries from the
  contract doc, and records the output verbatim.
- `docs/m1.2-report.md` — acceptance transcript from real commands; full
  regression; milestone commit; the dogfood Goal reaches `done`.

## M1.2 acceptance checklist (milestone gate)

1. `uv run pytest -q` exits 0 (suite grows from 386).
2. Schema v5 migrates an existing R001-era `state.db` in place
   (backup-replace-restore) and a fresh DB both pass the suite.
3. In this run's state: no attempt lacks `started_at`/`ended_at` after
   completion; the regression test locks the CLI worker path.
4. Host attempts in this run carry `session_ref`; `orx usage record`
   round-trips a `host_report` observation visible in `orx usage --json`
   with its accuracy.
5. This run's row exposes lifecycle `started_at`/`completed_at`.
6. `docs/observability-contract.md` exists and covers tables, join keys,
   per-runner token semantics, span-vs-wall-clock, accuracy-vs-coverage.
7. CLI token-observation coverage on this run is measured against the
   R001 baseline (12/37) and every miss carries a recorded reason.
8. `docs/m1.2-report.md` exists with the acceptance transcript and the
   six-metric first report.

## Risks

- CHECK-constraint rebuild on `usage_observations` touches live data →
  covered by the existing migration framework + its own tests.
- Harness session ids absent from captured output (cursor) → `session_ref`
  stays NULL for those attempts; coverage metric says so; never faked.
- Dogfood self-reference (the run measures itself) → measurements taken
  by the P3 task after P1/P2 code is live in the working tree; earlier
  attempts honestly appear as legacy-path rows.

## Routing

Planner `orx-host` (host dispatch). Workers default `cursor-economy`;
schema migrations, the contract doc, and phase integration route
`orx-host`. Verifications `cursor-economy`. CLI parallel cap 1.

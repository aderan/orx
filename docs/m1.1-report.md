## Task 2 — 可追溯的重规划输入

- `orx replan --context-file <file>`：本轮原因/意图/补充资料原文进入 planner
  prompt 的独立块（"Controller's intent for THIS replan round"）。
- `dispatch.replan_snapshot`：从 ORX 状态确定性生成事实快照 —— 全部修订、任务
  状态、passed、失败原因、证据与验证引用（含 exit code 与 log 路径）；缺失信息
  渲染为 `(unknown — no failure reason recorded)` / `(none recorded)`，不由模型
  猜测。
- planner prompt 三段分明：原始 Goal（原文在前）→ Execution Facts 快照 → 本轮
  intent；并写明边界规则（passed 是事实、绝不自动 pass、每版仍须逐字覆盖 Goal
  验收）。
- 实际输入落盘：host 路径 = assignments/P00x.md（等待指派被刷新而非静默复用）；
  CLI 路径 = launch/plan/prompt-<attempt>.md。
- 校验顺序：context 文件缺失/为空/超 64 KiB 时在路由、attempt、任何模型调用之前
  报错（测试证明 attempt/assignment 数量不变）。
- Goal 不被改写：intent 只进入 prompt，goals 表逐字节不变
  （`test_context_file_never_rewrites_the_goal`）。

## Task 3 — 计划替换边界

四场景契约测试（`tests/test_replacement_boundary.py`）：

1. 规划失败（CLI planner 崩溃）→ 原修订/任务状态逐字节不变。
2. 非法计划（缺依赖目标 / 验收未逐字覆盖）→ `PlanValidationError`，原计划不变。
3. running/verifying 任务 → `ReplanRejectedError`（plan_route 与 submit_plan 双
   入口，含带 --context-file 的调用）。
4. 成功替换 → 旧修订 superseded、未完结任务 cancelled、passed 保留为事实、新任
   务仅 pending/runnable（无自动 passed）、每版验收覆盖强制成立；准备阶段
   （plan_route 出指派）不取消任何旧任务。

## Task 4 — 跨阶段交接（stub）+ 真实试用

确定性场景（`tests/test_handoff.py`，不调用任何模型）：阶段1 passed → 阶段2 假设
失败 → Controller 意图文件 → planner 指派含（目标原文、T001 PASSED、失败依据、
验证引用、intent 原文、auto-pass 边界）→ 新计划提交（终态不改写：passed/failed
保留）→ 剩余任务执行验证 → Run/Goal done。CLI 层 `replan --context-file` 的成功
与失败（文件缺失 → exit 1，"cannot read"）路径均有测试。

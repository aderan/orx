# PBV 轮计划（reports/pbv/round-N-plan.md）生产模板

轮计划是每轮自包含的实施计划：它是 worker 能看到的唯一计划（经该 task 的
preread 首项传入），主计划全文永不进入构建上下文。必须**自包含且短小**——
worker 常驻上下文的大小直接决定成本（实测把主计划塞给每个构建代理，单代理
18–22M tokens）。

轮计划是**辅助实施文件**：生效任务的范围、验收与验证要求以 Plan IR 为准；
轮计划不得改变它们，与 Plan IR 冲突时以 Plan IR 为准。认为任务定义需要
变化（扩范围、改验收、改验证）时走 `orx replan`，不在轮计划里私自生效。
轮计划只回答"这一片具体怎么实施"。

线性链下 N 与 task 一一对应；**编号续接旧序列**：若 reports/pbv/ 已有旧
Goal 轮文件，从其最大编号 +1 起（Round 0 对齐一次，见 plan-review.md），
报告与计划同编号，绝不从 1 重起、绝不覆盖旧文件。

## 来源 A：planner 只读细化（首选）

在子代理中运行以下提示词（host 驱动下只读是提示词纪律；产物是项目文件，
**不改 Plan IR、不动任务图**）：

```text
你是规划者，为 PBV 第 <N> 轮细化实施计划。你在仓库根目录，只有只读权限，不改任何文件。

先读：当前切片 preread 清单点名的现有代码与测试文件，确认现状。
当前切片：<切片编号与标题、范围、验收标准原文>

产出中文实施计划（Markdown），必须包含下述全部小节：
1. 范围；2. 文件级改动清单；3. 测试计划；4. 实施顺序；5. 完成定义（逐条
对应验收标准原文）；6. 先读文件清单（worker 开工要读的全部文件，一次列全）。

纪律：只规划不实现；路径与符号必须真实存在；不确定处标注假设；计划必须
自包含——worker 不读主计划，验收标准与先读清单全部落在本文件里；短小，
不堆砌背景。
```

## 来源 B：Controller 机械抽取（次选）

从 Plan IR 该 task 条目直接抽取：objective → 范围；acceptance → 完成定义；
preread → 先读文件清单。文件级改动清单与实施顺序由 Controller 读码后按
依赖补齐。轮报告 Plan 段注明来源"Controller 抽取"。

## 轮计划文件必需小节

1. **范围**：本片做什么、明确不做什么。
2. **文件级改动清单**：新增/修改/删除，每个文件改什么、为什么。
3. **测试计划**：新增/修改哪些测试、覆盖什么行为（公共接口优先）。
4. **实施顺序**：最小步。
5. **完成定义**：逐条对应切片 acceptance（原文）。
6. **先读文件清单**：worker 开工要读的全部文件，含测试文件，一次列全。

任一小节缺失即不自包含，退回重产。修复轮不改轮计划——修复指令经内核
prior_failure 进入 worker prompt。
